There is a story the market wants to believe.

AI writes code.
Code is the expensive part.
Therefore engineers matter less.

That story is everywhere now.
In hiring plans.
In boardroom optimism.
In CEO fantasies about shipping more with fewer people.

And on the surface, it sounds plausible.
LLMs really can produce code.
A lot of it.
Fast.

So you would expect engineering to become less valuable.

Yet my reaction has been the opposite.

The more capable these tools become, the more I want to work with engineers.
Not less.

Something doesn't fit.

𓊍

If code generation were the same thing as engineering, the hype would make sense.

But anyone who has built real software knows that code was never the whole game.
The hard part was never just producing enough syntax.

The hard part was deciding what should exist.
What should not.
Where the complexity actually lives.
Which shortcut is harmless.
Which shortcut quietly poisons the system six months later.
Which abstraction will stretch.
Which one will snap.

An LLM can help you make something.
That is useful.

But software is not merely something.
It is a system.

Systems carry constraints.
Dependencies.
Failure modes.
Security risks.
Maintenance costs.
Human consequences.

That is why two people can use the same model and produce very different results.
Not just different code.
Different futures.

One produces something that demos well.
Another produces something that survives contact with reality.

That difference is not in the model.
It is in the engineer.

𓊍

The more I think about it, the more this looks like a bottleneck shift.

AI lowers the cost of production.
So production stops being the scarce thing.

When a machine can generate ten implementations where a human used to generate one, the leverage does not disappear.
It moves.

Now the valuable act is not generation.
It is selection.

Which path is robust?
Which path is readable?
Which path creates hidden coupling?
Which path makes the next change cheaper instead of harder?
Which path solves the real problem instead of just producing output that compiles?

These are not typing problems.
They are judgment problems.

And judgment is only half of it.
The other half is taste.

Not visual taste.
Engineering taste.

The ability to see a cleaner shape.
To remove a layer instead of adding one.
To collapse complexity with a better framing.
To know when the clever move is wrong.
To recognise when the system is telling you to redesign the idea, not extend the code.

That is the part I want more of.
That is why I would rather work with an AI-equipped engineer than prompt an LLM in a vacuum.

𓊍

This is what people miss when they say AI will replace engineers.

They are treating code as the unit of value.
But code was only ever an intermediate artifact.

What companies actually buy is not syntax.
They buy sound decisions.
They buy coherent systems.
They buy reliable trade-offs.
They buy someone who can be responsible for the whole thing.

Perhaps the real shift isn't that engineering is becoming less important.

It is that once code gets cheap, taste gets expensive.

The scarce resource is no longer the ability to produce code.
It is the ability to judge it.
Shape it.
Restrain it.
Turn abundance into something coherent.

That is why I still need engineers.
Maybe more than before.

Not as typists.
As people who can turn infinite generation into a system worth trusting.
